Disaster Casualty Management System

Current Progress and Achievements

A full-stack emergency response platform with an installable mobile PWA, role-based casualty workflows, triage algorithm support, admin verification, incident management, and deployment-ready cloud architecture.

Mobile PWA Admin Web Dashboard Express API Supabase Database Render + Netlify Deployment
Prepared August 26, 2026

Executive Summary

What Has Been Built

3 Major application surfaces: mobile PWA, admin website, backend API.
5 Primary operating roles supported across responder, documenter, admin, and super admin flows.
3 Triage stages supported: primary, secondary, and tertiary.
Cloud API on Render, frontend apps on Netlify, database/auth on Supabase.

Operational Goal

Reduce repetitive encoding during disaster response by separating official incident setup from casualty logging, then allowing responders and documenters to work from the correct incident context.

Clinical Data Goal

Keep responder-entered triage separate from system-calculated triage so overtriage and undertriage can be measured without biasing users during data entry.

01 / Overview

System Architecture

Major Components and Connections

Mobile PWA

Expo React Native app exported for web and installed through mobile browsers.

  • Responder casualty entry
  • Healthcare facility documentation
  • Role-based quick actions
  • Offline local storage support
  • PWA manifest and service worker

Backend API

Node.js and Express API hosted on Render.

  • Authentication and account management
  • Incident and casualty endpoints
  • Triage calculation logic
  • Verification workflows
  • Action logs and SitRep support

Admin Website

Desktop web dashboard for administrators and super administrators.

  • Official incident setup
  • Account management
  • Verification review
  • Incident management panels
  • Unit-scoped administrative views

Database and Auth

Supabase provides PostgreSQL storage and authentication. Main data areas include users, incidents, casualties, triage assessments, transport, treatment, hospital care, verification, and action logs.

Deployment Model

Render serves the API. Netlify serves the mobile PWA and the desktop admin website. Local testing uses Vite/Expo builds, static serving, and ngrok when external device access is needed.

03 / Mobile PWA

Role-Based Workflows

Add Casualty by User Role

Role / Function Current Behavior Purpose
Field Responder Shows safety prompt, PPE time, primary triage fields, triage assessment, triage time, and limited status/notes. Fast first-contact casualty tagging at the scene.
Stabilization Area Responder Uses the expanded casualty workflow with safety prompt, intro, victim info, address, secondary triage, care/treatment, transport, and notes. More complete documentation once the casualty reaches stabilization care.
Healthcare Facility Documenter Uses hospital-focused fields for receiving facility details, patient information, tertiary triage, management, resources, disposition, and facility disruption. Captures ED and hospital care information after patient arrival.
Admin / Super Admin Receives admin-focused quick actions, incident records, verification review, account management, incident management, and action logs. Coordinates incident data quality, official records, and user administration.

Responder Function Selection

Responder accounts can choose whether they are Field Responders or Stabilization Area Responders from the profile flow. The selected function controls the Add Casualty fields.

Conditional Form Behavior

Healthcare and treatment fields are conditionally active using parent-child relationships, so dependent fields appear only when their parent answer makes them relevant.

Triage

Triage Systems and Accuracy Logic

Primary Triage

START STIEVE mSTART JumpSTART SIEVE Care Flight SALT PTT MITT Homebush MPTT STM pending algorithm validation

Secondary Triage

SAVE SORT META SwiFT pending algorithm validation SMART Urgent / Non-urgent Other

Tertiary Triage

NATO MASS ESI METTS Other

Implemented Logic

  • User-entered final triage is stored separately from system-calculated triage.
  • Triage category field was removed from normal manual entry.
  • Assessment popup appears after selecting a triage system.
  • Final triage choices use color-coded, even layouts.
  • One answered assessment item can allow forward progress where rapid entry is needed.

Accuracy Protection

  • Overtriage and undertriage summaries are hidden from normal users during entry.
  • Expectant is treated consistently with black/T4 for supported comparisons.
  • Unknown is excluded from accuracy calculations.
  • ESI and METTS are excluded from T1-T4 accuracy formulas until a separate reporting rule is approved.
